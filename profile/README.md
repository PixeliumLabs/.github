# PixeliumLabs

> **Software with character. Built for every screen.**

**PixeliumLabs** is an independent software laboratory focused on creating digital experiences with personality, simplicity, and a touch of nostalgia.

Our goal is to build a **multiplatform suite of applications**, combining modern technologies with an aesthetic inspired by the classic era of desktop software.

Our current focus is the **Retro App Suite**, an ecosystem of applications for **Windows and Android**, built with a modular architecture and designed to grow alongside the organization.

---

## 🧪 What is PixeliumLabs?

PixeliumLabs was born from a simple idea:

Software doesn't have to be purely functional.

It can have:

* identity;
* personality;
* memorable visual details;
* playful interfaces;
* consistent experiences;
* and that little something that makes you remember an application after you close it.

We want to explore the space between **modern software** and the **aesthetic of classic applications**.

Rather than simply recreating old interfaces, we aim to reinterpret their visual language for today's devices.

**Retro at heart. Modern underneath.**

---

# 🖥️ Retro App Suite

The main project at PixeliumLabs is a collection of small, independent applications that share the same visual and technological identity.

The idea is to create a kind of **digital toolbox**, where each application solves a specific problem while still feeling like part of the same universe.

### 🎨 Visual Philosophy

The interface takes inspiration from:

* classic Windows applications;
* skeuomorphism;
* compact utility software;
* strong borders and shadows;
* pixel art;
* older operating systems;
* desktop utilities;
* and software designed to simply **work**.

But we don't want to be trapped in the past.

The retro aesthetic is our starting point. The engineering remains modern, responsive, and multiplatform.

---

## 🧩 Architecture

The suite is designed around a modular architecture.

Each application should be able to evolve relatively independently while shared components provide a common foundation across the ecosystem.

```text
PixeliumLabs
│
├── Retro App Suite
│   ├── App A
│   ├── App B
│   ├── App C
│   └── ...
│
├── Pixelium UI
│   ├── Components
│   ├── Themes
│   ├── Icons
│   └── Design Tokens
│
└── Shared
    ├── Utilities
    ├── Services
    └── Core
```

The goal is to avoid turning every application into an isolated island.

When a component, behavior, or solution is improved, that knowledge should benefit the rest of the suite whenever possible.

# 🎯 Principles

### 01. Software with personality

We don't want generic interfaces.

Every application should feel like it belongs to PixeliumLabs.

### 02. Simplicity first

A tool should be easy to understand before it becomes packed with features.

### 03. Small details matter

Borders, shadows, interaction states, animations, sounds, and micro-interactions are all part of the experience.

Sometimes a tiny visual detail is what turns an ordinary interface into a memorable one.

### 04. Retro doesn't mean outdated

The aesthetic can look backward.

The engineering doesn't have to.

### 05. Multiplatform for real

The goal isn't simply to make an application "run" on multiple platforms.

We want it to **feel right** on each of them.

### 06. Experimentation

Not every idea has to work.

PixeliumLabs is a laboratory, after all.

Experimental components, unusual ideas, prototypes, and solutions that may eventually be thrown away are all part of the process.

# 🧱 Pixelium UI

An important part of the ecosystem is the creation of a shared visual language.

**Pixelium UI** brings together the components, styles, and patterns used throughout the suite.

This includes things such as:

* buttons;
* text fields;
* panels;
* menus;
* cards;
* toolbars;
* dialogs;
* icons;
* hover states;
* focus states;
* pressed states;
* disabled states;
* shadows;
* borders;
* themes;
* and reusable UI components.

The long-term goal is to gradually build a **design system of our own**, rather than relying exclusively on the default components provided by each platform.

---

# 🖱️ Interaction

One of the things we want to explore is software that genuinely responds to the user's actions.

For example:

```text
Normal
   ↓
Hover
   ↓
Pressed
   ↓
Active
   ↓
Disabled
```

Each state should have a clear visual purpose.

Small changes in position, shadow, border, or color can communicate exactly what is happening.
